정렬 알고리즘의 성능 및 안정성 비교

## 1. 무작위 데이터 100회 반복 실험 결과 (N = 10,000)
- **선택 정렬 (Selection Sort)**
  - 총 비교 횟수: 4,999,500,000 / 평균 비교 횟수: 49,995,000 / 평균 이동 횟수: 29,997
- **버블 정렬 (Bubble Sort)**
  - 총 비교 횟수: 4,999,500,000 / 평균 비교 횟수: 49,995,000 / 평균 이동 횟수: 약 74,990,000
- **조기 종료 버블 정렬 (Bubble Sort - Early Termination)**
  - 총 비교 횟수: 약 4,999,400,000 / 평균 비교 횟수: 약 49,994,000 / 평균 이동 횟수: 약 74,990,000
- **삽입 정렬 (Insertion Sort)**
  - 총 비교 횟수: 약 2,500,700,000 / 평균 비교 횟수: 약 25,007,000 / 평균 이동 횟수: 약 25,017,000

## 2. 일반 버블 정렬과 조기 종료 버블 정렬 비교
- **무작위 / 역순 데이터**: 마지막 패스 근처까지 교환이 발생하므로 비교 횟수 차이가 거의 없음.
- **이미 정렬된 데이터**: 일반 버블 정렬은 49,995,000회 비교하나, 조기 종료 버블 정렬은 첫 번째 패스(9,999회 비교)에서 교환이 0회임을 확인하고 즉시 종료하여 비교 횟수가 99.98% 감소함.
- **일부 정렬된 데이터**: 뒤쪽 패스에서 정렬이 일찍 완료될 경우 불필요한 잔여 패스를 생략하여 비교 횟수가 감소함.

## 3. 안정성(Stability) 검증 방법 및 결과
- **검증 방법**: 구조체에 초기 입력 순서(`orig_idx`)를 저장하고, `key1`이 중복되도록 생성한 데이터(예: `(527, 100, idx:0), (527, 200, idx:1), (125, 300, idx:2), (892, 400, idx:3)` 및 중복 키 10,000개 배열)를 정렬한 뒤, 인접한 동일 `key1` 원소 간 `orig_idx`가 오름차순(`arr[i].orig_idx < arr[i+1].orig_idx`)을 유지하는지 검사함.
- **선택 정렬**: `Unstable (불안정)` — `[0](527, 100), [1](527, 200), [2](125, 300)`에서 첫 패스에 `[0](527, 100)`과 최솟값 `[2](125, 300)`이 직접 교환되면서 `[0]`이 `[1](527, 200)` 뒤로 이동해 상대적 순서가 역전됨.
- **버블 정렬**: `Stable (안정)` — 인접한 원소끼리만 비교하며 `arr[j].key1 > arr[j+1].key1`일 때만 교환하므로 같은 키끼리는 서로를 넘어가지 않음.
- **삽입 정렬 (`>`)**: `Stable (안정)` — 앞선 원소가 현재 원소보다 클 때만 뒤로 밀어내고, 같은 키를 만나면 그 바로 뒤에 삽입하므로 원래 순서가 유지됨.
- **삽입 정렬 (`>=`)**: `Unstable (불안정)` — 앞선 원소와 키가 같을 때도 앞선 원소를 뒤로 밀어내므로, 나중에 입력된 데이터가 먼저 입력된 데이터의 앞으로 삽입되어 순서가 역전됨.

## 5. 부분 정렬 데이터 생성 방법 (AI 활용)
- **생성 방식**: AI를 통해 부분 정렬 데이터 생성 기법(구간 섞기, 인접 노이즈 추가, 무작위 쌍 교환)을 조사한 후, 오름차순 정렬된 10,000개 배열에서 전체 크기의 5%에 해당하는 500쌍의 인덱스를 무작위로 선택해 교환(Random Perturbation)하는 방식을 적용함. 전체적인 정렬 경향성을 유지하면서 국소적인 역전(Inversion)을 발생시킴.

## 6. 초기 정렬 상태에 따른 알고리즘별 성능 원인 분석
- **선택 정렬**: 데이터의 정렬 상태와 무관하게 매 패스 남은 전체 원소를 순회하므로 비교 횟수가 항상 $N(N-1)/2$로 고정되며, 교환도 매 패스 1회(이동 3회)만 수행되어 데이터 이동 횟수가 가장 적고 일정함.
- **버블 정렬**: 일반 방식은 초기 상태와 무관하게 비교 횟수가 고정되나, 역순일 때 매 비교마다 교환(이동 3회)이 발생해 이동 횟수가 급증함. 조기 종료 적용 시 이미 정렬된 데이터에서 $O(N)$ 비교만으로 종료됨.
- **삽입 정렬**: 이미 정렬된 영역의 뒤에서부터 비교하다가 자신보다 작거나 같은 값을 만나면 즉시 탐색을 멈추므로, 정렬도가 높을수록(정렬 데이터, 부분 정렬 데이터) 비교 및 이동 횟수가 $O(N)$에 가깝게 급감함. 반면 역순 데이터에서는 매번 맨 앞까지 비교·이동해야 하므로 $O(N^2)$의 최악 성능을 보임.
